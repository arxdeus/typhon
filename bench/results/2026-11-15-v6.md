## Pre-fix pass (same HEAD, stock runtime)
Runtime CPU T/C was the same as above except np_small_linalg 1.03, np_eigh_svd 1.03, np_solve_chol 1.02 (0.01 s granularity).
Two re-measures (1 build + 11 runs each): eigh_svd 2.45/2.48 then 2.47/2.46 (noise). solve_chol 2.42/2.45 then 2.46/2.46.
A paired internal-timer run (15x) gave 2.378 vs 2.391 (+0.5%, noise). small_linalg was 0.61/0.63 in all 3 passes, so it was real.
Peak RSS max for np_eigh_svd varies from run to run (C++ 127 to 143 MB, Typhon 135 MB). The medians are 112 vs 112 MB.

## Fix: bdwgc size classes (np_small_linalg)
`GC_DONT_GC=1` made both sides equal (0.599 vs 0.601), so the gap was in the GC. Typhon allocated 959 MB vs 784 MB (161 vs 159 GCs).
Per op, `np.linalg.solve(8x8)` allocated 1122 B per call vs 791 B. The 640 B LAPACK work buffer was a 1024 B object
(`GC_size`) vs 672 B in C++. bdwgc creates size classes lazily, and the class depends on request order. numpy's startup
`sctypeDict` (an 840 B table) came first, so the 1024 B class covered 641..1024. Fix: `seed_size_classes()` at GC init
allocates and frees one object per class, 1..2048 ascending. That gives order-independent classes 512/672/800/1024/1344/2048.
After: 780 MB allocated, 160 vs 159 GCs, same GC time (47 vs 50 ms). 21x paired internal timer: C++ 0.6186, old 0.6371 (+3.0%),
new 0.6333 (+2.4%). With GC off, about 1.5% remains (`GC_DONT_GC`: 0.595 vs 0.606, +1.2% instructions). That is inside
Accelerate/LAPACK (the call sequence matches) plus bdwgc 8.3 vs 8.2.12 locking (`GC_generic_malloc_many`, mutex), and is close to noise.
Tests with the patched runtime: types/core/stdlib/numpy/scipy/robot/bci all pass, check_lda_regression PASS.
After e3b4a640 in release (stock target/release, 11 interleaved runs, medians): CPU C++ 0.61 vs Typhon 0.62 s (T/C 1.016),
peak RSS 13.3 vs 12.4 MB. Before (table above): 0.620 vs 0.630.

## go_cy
Fails in both ("'Board' does not match expected type ''Board''"). It is a shared language limitation, not a Typhon bug:
a string annotation is typed as a literal `str` type. Without the quotes, both report "name 'Board' is not defined",
because a class field annotation cannot refer to a class defined later. go_cy.py is the Cython-only copy (Cython rejects
PEP 695 generics). `go.py` (the same algorithm with `class Square[Board]`, as in the original go.codon) is the Typhon/C++ benchmark.
Supporting forward references needs deferred class-field resolution in the typechecker. That is not cheap and not done.
